Tools for looking at a code-task run directory (the files a run leaves behind: contract.json, result.json, memo.sqlite, events.jsonl, verdict_<i>.json). Three things to do. Change only scripts/audit_run.py, scripts/failure_trace.py, scripts/pilot_report.py (new) and evals/runlog.py (new); everything else, the tests included, is protected.

1. Shared reader. Add evals/runlog.py, the one place that reads a run directory: the events of events.jsonl together with the number of non-blank lines that did not decode (read with harness.events.parse_lines, which skips an undecodable line wherever it is), result.json (None when the run has none), and the memo. scripts/audit_run.py, scripts/failure_trace.py and the new scripts/pilot_report.py must read runs through it.

2. Keep what the two inspectors print. For a run that finished normally, scripts/audit_run.py RUN_DIR and scripts/failure_trace.py RUN_DIR [RUN_DIR ...] must print exactly what they print today, byte for byte: line order, spacing, the truncation of texts, the hash ok/MISMATCH lines, the result summary and the '##### <name>' headers. Exactly three things change, and each of them is a crash today:
 a. A line of events.jsonl that does not decode (a process killed in the middle of a write leaves one, and after a resume it is no longer the last line) is skipped wherever it is. The output is then the same as for the log without that line, plus one last line 'events skipped: N', printed only when N is greater than 0.
 b. audit_run.py on a run that made no model call (for example one BLOCKED before the first call, whose result has 'tools': null) does not crash. It prints 'effective tools None', 'llm_call_started 0, llm_call 0 (ok 0, refused 0)', 'prompt_hash checked 0, mismatches 0', then the notable events and the result line as usual, and exits 0.
 c. failure_trace.py on a directory that has no result.json prints '##### <name>: no result.json' (name is the directory's name) and goes on with the next argument.

3. A report over runs. Add scripts/pilot_report.py: python scripts/pilot_report.py RUN_DIR [RUN_DIR ...] [--supervision FILE.json]. It prints one JSON object {"runs": [...], "summary": {...}} (indent 2, keys in the order below) and exits 0. FILE.json maps a run id (the directory's name, also when it is given with a trailing slash) to minutes of supervision (a number, 0 or more); a run it does not name has none, and a name that matches no run is ignored. Nothing is guessed from what the files do not hold.
Per run, in the order of the arguments: run_id; status (result.json's status, or 'NO_RESULT' when the run has no result.json); done (status is 'DONE'); attempts, llm_calls, usd_billed (from result.json, null without one); cost_known (evals.score.cost_is_known on result.json, which you must use, never redefine; false for NO_RESULT); events_skipped (result.json's value when it has one, otherwise the number counted by the reader); supervision_minutes (null when there is none, never 0).
Summary, in this order: runs; done; no_result; success_rate = done / (runs - no_result), null when that is 0 (a NO_RESULT run is neither a success nor a failure); usd_known_total = the sum of usd_billed over the runs whose cost is known (failed runs included), null when no run has a known cost; usd_unknown_runs = the runs whose cost is not known (NO_RESULT ones included); cost_per_success = usd_known_total divided by the number of DONE runs among those with a known cost, null when there is none; cost_complete = true only when usd_unknown_runs is 0; attempts = {mean, median over the DONE runs, null when there is none; distribution: {"<attempts>": number of runs} over the runs that have a result.json, keys as strings in increasing order}; supervision_minutes = {runs_with_data, total, mean} over the runs that have a value, total and mean null when there is none; events_skipped = the sum over the runs. An unknown cost is never counted as 0. Numbers are rounded to 6 decimals.
The command is refused, with 'refused: <reason>' on stderr, nothing on stdout and exit code 2, when an argument is not a run directory (it has no events.jsonl; the reason says 'not a run directory') or when the supervision file cannot be read, is not a JSON object, or has a value that is not a number of 0 or more (a boolean, a string, null and a negative number are not valid; the reason mentions 'supervision').
