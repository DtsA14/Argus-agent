## The issue

value_chain swallows a TypeError raised while iterating an argument

`value_chain` treats a `TypeError` raised *while consuming* an argument as evidence that the argument is not iterable. The exception is swallowed, and the partially-consumed object is emitted into the output stream after the items it already produced.

### Reproduction

```python
>>> from more_itertools import value_chain
>>> list(value_chain(map(len, ['ab', 'cde', 5])))
[2, 3, <map object at 0x104c6e530>]
```

The `TypeError: object of type 'int' has no len()` never reaches the caller. The trailing item is the exhausted `map` object itself, so it carries no data:

```python
>>> out = list(value_chain(map(len, ['ab', 'cde', 5])))
>>> list(out[-1])
[]
```

`itertools.chain` and more-itertools' own `always_iterable` both propagate on the same input:

```python
>>> list(chain(map(len, ['ab', 'cde', 5])))
TypeError: object of type 'int' has no len()
>>> list(always_iterable(map(len, ['ab', 'cde', 5])))
TypeError: object of type 'int' has no len()
```

Any lazy argument can trigger this — a generator, a `map`, a file-backed iterator — so a genuine bug in caller code is reported as a stray object in the output rather than as an exception.

### Cause

[`more.py` L4416](https://github.com/more-itertools/more-itertools/blob/bc8be10/more_itertools/more.py#L4416):

```python
        try:
            yield from value
        except TypeError:
            yield value
```

`yield from` consumes lazily, so the guard stays active for the entire consumption of `value` instead of only classifying it. The `except` branch is meant to catch the classification failure — an object that cannot be iterated — but it also catches every `TypeError` produced downstream while iterating.

Present since `8dbf8ae` (2020-12-01), the commit that added `value_chain`. Reproduces on released 11.1.0.

### Suggested fix

Classify with `iter()`, then consume outside the guard:

```python
        try:
            it = iter(value)
        except TypeError:
            yield value
        else:
            yield from it
```

This is what the sibling `always_iterable` already does. Objects that cannot be iterated at all — including those whose `__iter__` raises `TypeError` — are still emitted as-is, so the documented behaviour is unchanged.

I have a branch with this fix and regression tests ready and will open a PR against this issue.

```python
    def test_type_error_while_iterating(self):
        # A TypeError raised while consuming an argument means the argument
        # is broken, not that it is a scalar - it should propagate.
        def gen():
            yield 1
            yield 2
            raise TypeError('failure inside the iterable')

        it = mi.value_chain(gen(), 3)
        self.assertEqual([next(it), next(it)], [1, 2])
        with self.assertRaises(TypeError):
            next(it)

    def test_type_error_from_iter(self):
        # An object that cannot be iterated at all is still emitted as-is.
        class NotIterable:
            def __iter__(self):
                raise TypeError('not iterable')

        obj = NotIterable()
        self.assertEqual(list(mi.value_chain(1, obj, [2, 3])), [1, obj, 2, 3])
```

```python
    def test_type_error_while_iterating_a_map_propagates(self):
        try:
            list(mi.value_chain(map(len, ['ab', 'cde', 5])))
        except TypeError as exc:
            self.assertIn('len()', str(exc))
        else:
            raise AssertionError(
                'value_chain swallowed the TypeError raised while iterating '
                'an argument instead of propagating it'
            )

    def test_items_before_iteration_error_are_yielded(self):
        iterator = mi.value_chain(map(len, ['ab', 'cde', 5]))
        self.assertEqual(next(iterator), 2)
        self.assertEqual(next(iterator), 3)
        try:
            next(iterator)
        except TypeError:
            pass
        else:
            raise AssertionError(
                'value_chain yielded the partially consumed argument instead '
                'of propagating the TypeError raised while iterating it'
            )

    def test_generator_type_error_propagates(self):
        def raiser():
            yield 'a'
            raise TypeError('iteration failed')

        iterator = mi.value_chain(raiser())
        self.assertEqual(next(iterator), 'a')
        try:
            next(iterator)
        except TypeError:
            pass
        else:
            raise AssertionError(
                'value_chain swallowed the TypeError raised by a generator '
                'argument instead of propagating it'
            )

    def test_argument_whose_iter_raises_type_error_is_emitted_as_is(self):
        class NotIterable:
            def __iter__(self):
                raise TypeError('cannot be iterated')

        obj = NotIterable()
        self.assertEqual(list(mi.value_chain(obj)), [obj])
```
