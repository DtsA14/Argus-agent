## The issue

split_before/split_after/split_when disagree with themselves on an empty iterable when maxsplit=0

`split_before`, `split_after` and `split_when` return a different result for an empty iterable when `maxsplit=0` than they do for any other `maxsplit`, even though no split can occur either way.

```python
>>> import more_itertools as mi
>>> pred = lambda x: x == 0
>>> {ms: list(mi.split_before([], pred, maxsplit=ms)) for ms in (-1, 0, 1, 2)}
{-1: [], 0: [[]], 1: [], 2: []}
```

`split_after` and `split_when` behave the same way. `split_at` is consistent (`[[]]` at every `maxsplit`, matching `''.split(',', 0) == ['']`).

The `[]` answer is the one the library already pins: `tests/test_more.py:1548` asserts `list(mi.split_before([], ...)) == []` and `tests/test_more.py:1689` asserts the same for `split_when`. Neither test passes `maxsplit`, so neither reaches the fast path that produces `[[]]`.

The fast path is:

```python
if maxsplit == 0:
    yield list(iterable)
    return
```

added to all four functions in f77823f (2020) as a speed shortcut, when `split_before` still ended with a bare `yield buf` and `[[]]` was its correct empty-input answer. 2e81a56 (2021) later changed the terminal yield to `if buf: yield buf` and added `test_empty_collection`, but did not reach behind the fast path.

Happy to open a PR guarding the fast path the same way the slow path already is, leaving `split_at` alone.

    """An empty iterable yields no pieces, whatever *maxsplit* is"""

            actual = list(
