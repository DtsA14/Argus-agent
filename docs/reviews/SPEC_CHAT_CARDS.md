## 1. Masalah dan ukuran
Dari HP, Atha hanya bisa membaca job issue di chat. PRD (folder 1-5 issue) dan antreannya hanya terbaca di terminal lewat ringkasan Claude; pilot Rp1 memperlihatkan akibatnya (angka salah ditangkap Claude, bukan layar). T1 membuat contoh dijalankan mesin; T2 **menampilkannya**. Ukuran: (1) tiap contoh di kartu menampilkan panggilan, nilai yang diharapkan, hasil jalan dan status **dari berkas mesin**, tanpa parafrase; (2) Atha bisa membuka PRD (teksnya) dan antreannya dari HP; (3) hasil yang bisa gagal (intake dan audit kode, bukan hanya hasil penulis) ikut tampil; (4) tanpa tombol (aksi = T4, sesudah T3).

## 2. Prinsip
- **Hanya baca, hanya GET.** Tidak ada POST baru, tidak ada proses (tidak ada `subprocess`, `fork`, `git`), tidak ada model, tidak ada tulis. Rute baru ada hanya bila chat punya `Actions` (seperti rute issue) dan tunduk pada Host dan fetch-site yang sama (SPEC_CHAT_APP 11.1) pada semua metode.
- **Sumber tidak baru**: `job.json`, `issue.txt`, `prd-<turn>/*`, `queue.json`, `issue-N.md` antrean, `examples_intake.json`, `examples_audit_<sid>.json`. Tidak ada berkas atau kolom baru.
- **Asal tiap bidang ditandai** (kolom "asal" di bagian 4): `mesin` (nilai yang harness validasi: id, tingkat, status, state, sha), `model` (teks atau kode tulisan model, ditandai di layar), `keluaran-kode` (apa yang dicetak kode contoh; diberi label data). Baris status `e1 · whatif · pass` hanya memakai bidang `mesin`.
- **Apa arti `pass`** (ditulis di layar): kode contoh melaporkan cocok di sandbox; kode itu ditulis model dan bisa memalsukannya (SPEC_EXAMPLE_GATE 5). `pass` bukan bukti bahwa aturan di prosa benar.
- **Pengikatan**: status hanya tampil bila berkas yang dibaca sama dengan yang dihitung statusnya (bagian 5). Bila tidak: `results: null`, `why` menyebut sebabnya; **tidak ada status sama sekali**.

## 3. Rute, bacaan, batas
Semua GET, di `router/chat.py` (`/api/cards*`), bacaan di `router/chat_actions.py`. Pola: job `UI_ID`; antrean `rq.QUEUE_ID`; `turn` harus fullmatch `w[0-9]{1,3}` sebelum `_open_dir`; `n` item antrean int 1..8. Setiap bacaan: satu nama demi satu lewat fd direktori yang sudah dibuka, `O_NOFOLLOW|O_NONBLOCK`, `fstat` harus berkas biasa sebelum dibaca (FIFO ditolak), batas ukuran: `job.json` `JOB_JSON_MAX`; `PRD.md` 64 KB; `issues.json` 64 KB; `issue-N.md` `sd.TEXT_MAX` (256 KB); `queue.json` 100 KB; `examples_*.json` 64 KB; `issue.txt` `sd.TEXT_MAX`.
- `GET /api/cards` → `{rows: [...], truncated: bool}`; paling banyak 200 direktori job dan 200 antrean dipindai, 50 baris; urut `at` turun lalu id; tidak membaca ledger. Baris: `{id, kind: "prd"|"queue", title, state, repo, at, items}`. Job PRD: `at` = `created_at`, `title` = baris pertama pesan manusia pertama (teks manusia, di-`scrub`), `state` = state job, `items` = `prd_turns[-1].items` atau null. Antrean: `at` = `created_at`, `title` = `q.prd.dir` induk bila ada, `state` = bagian 4.3, `items` = jumlah.
- `GET /api/cards/prd/<job>`, `GET /api/cards/queue/<id>`; tambahan bidang `examples` pada `GET /api/issues/<job>` (bagian 4.1). Rute lain tidak berubah.
- Direktori antrean = `rq.QUEUES` atau `chat serve --queues-dir` (diberikan operator saat memulai layanan), **tidak pernah dari klien**. Daftar antrean: `os.listdir` pada fd direktori, nama harus fullmatch `QUEUE_ID`, dibuka dengan `_open_dir` + `_read_at` dengan bentuk yang sama dengan `rq._load`. Antrean yang `jobs_dir`-nya bukan direktori job chat (perbandingan string) tampil `items: null, why: "jobs dir lain"` dan job-nya tidak dibuka.
- **404**: id tidak cocok pola; direktori hilang atau symlink; `job.json` tak terbaca, melebihi batas, atau `kind` bukan yang diminta (`/api/cards/prd/<issue-job>` 404); antrean gagal bentuk `_load`. **200 dengan `why` per bidang**: folder atau berkas issue tak terbaca, terlalu besar atau sha-nya tidak cocok.

## 4. Bentuk kartu (JSON persis; urutan contoh = urutan blok)
Teks string = `scrub(s)` (fungsi yang ada, dengan penanda `[withheld by the harness: ...]`). Nilai JSON (`actual`, `expect`, `overrides`) = `scrub(json.dumps(v, sort_keys=True, ensure_ascii=False))` menjadi string. Setelah kartu jadi, `sd.KEY` dicek atas `json.dumps` seluruh jawaban: bila kena, bidang `examples` kartu itu diganti `{"withheld": true}` (kunci yang terpecah antara `setup` dan `run`).

### 4.1 Contoh (satu objek per issue atau item)
`examples = {"calls": [...], "results": [...] | null, "why": str|null, "no_examples": str|null, "note": str|null, "tier_moves": [...]}`
- `calls[i]` = `{id (mesin), tier (mesin), setup (model), run (model), expect | raises (model), overrides (model), says (model)}` dari blok `argus-examples` di teks issue lewat `eg.extract` (teks yang sama yang code job akan lihat). Id ganda atau hasil dengan id yang tidak ada di `calls`: seluruh bidang `examples` ditahan (`results: null, why: "id tidak cocok"`).
- `results[i]` = `{id, tier, status (mesin ∈ pass|fail|error|invalid|unchecked|not_run), actual | base_actual (keluaran-kode), where: "penulis"|"intake"|"audit"}`; divalidasi ulang seperti `eg._result` (status dalam `STATUSES`, tier dalam `TIERS`, `ex.shown` sekali lagi). `not_run` (token, bukan prosa) dengan `why` ("dijalankan saat job code item ini mulai") hanya bila tidak ada job code atau berkas intake `none`.
- `no_examples` (model), `note` (mesin: `environment tanpa pelari contoh`), `tier_moves[i]` = `{id, from, to}` (`id` berpola `e[1-9][0-9]?`, tier dalam TIERS, selain itu dibuang).
- **Pengikatan** (blocker rev 0): hasil tampil hanya bila (issue) `sha256(isi issue.txt) == data.issue_sha256` **dan** `eg.digest(contoh dari blok) == eg.digest(contoh yang tersimpan bersama hasil)`; (PRD) `rp.folder_sha` atas byte `PRD.md`, `issues.json`, `issue-N.md` yang dibaca == `turn.folder_sha` dan digest sama per item. Bila tidak: `results: null, why: "berkas tidak cocok dengan hasil"`.

### 4.2 Kartu issue (`GET /api/issues/<job>`, bidang tambahan `examples`)
Pesan penulis `m` yang dipakai = pesan penulis dengan `m.issue_sha256 == data.issue_sha256` (aturan yang sama dengan `issue.status_lines`), **bukan** `conversation[-1]`. Tidak ada: `examples: null`. Pesan tanpa `examples` (sebelum PR 3): `{"absent": true}`. Halaman issue menampilkan `eg.without_block(teks)` bila kartu contoh tampil, supaya `says` tidak muncul dua kali tanpa tanda. Sesudah `HANDED_OFF`, `results` mendapat dua tambahan dari job code (`handoff.job`, 4.4).

### 4.3 Kartu PRD (`/api/cards/prd/<job>`)
`{id, state, repo, turn ("w3"), commit12 (commit turn), inputs_commit12, stale (commit turn ≠ inputs), superseded (berkas SUPERSEDED ada di prd-<turn>), folder_sha12, prd_md (model, scrub), items: [{n, title (model: baris pertama), text (model: scrub(eg.without_block(issue))), touches, creates (model), clashes: [{file, line, why} (model)], examples (4.1)}], warnings (mesin), questions (model), money: {job_cap, spent (null bila tak terbaca), queue_usd}, queues: [qid]}`. Turn sebelum PR 3 tanpa `examples`: `examples: null` (`or [None]*n` seperti `status_lines`). `stale` atau `superseded`: layar menampilkan status redup dengan "hasil di commit lama". `queues` = antrean yang `q.prd.dir` induknya job ini (nama induk harus cocok `UI_ID` dan kakeknya sama dengan direktori job chat; `prd.dir` tidak pernah dibuka).

### 4.4 Kartu antrean (`/api/cards/queue/<id>`)
`{id, state, repo, jobs_dir_ok, items: [{n, title (model), text_matches (bool: sha256 issue-N.md == items[n].issue_sha256), job, job_state (mesin), applied: commit12|null (dari entri log `state`→APPLIED dengan `commit`, hanya bila `as_is` true), spent, examples (4.1, dengan results dari job code)}], next (mesin; `scrub`), closed (note manusia, scrub)}`.
- `state` = state `rq.derive` (`PENDING|WAITING|STOPPED|DONE|CLOSED`) **dihitung oleh salinan di chat yang membaca job item lewat fd dari direktori job chat, tanpa memeriksa HEAD dan tanpa git**. Di tempat `derive` akan bilang NEXT, kartu bilang `WAITING` dengan `next = "item k bisa mulai (HEAD tidak diperiksa dari chat)"`. `next` selain itu = `detail` dari `derive` (mekanis); `actions` (baris CLI) **dibuang**, tidak ditampilkan.
- Hasil dari job code (item atau issue yang HANDED_OFF): `examples_at_base` dari `jobs/<code>/examples_intake.json` (kunci `eg.intake_key(intake.snapshot_sha256, examples)`) dan `examples_after_agent` dari `examples_audit_<sid>.json` (sid = agent terakhir; kunci `eg.audit_key(stages[sid].review.patch_sha256, examples)`); keduanya dibaca lewat fd (batas 64 KB) dengan jenis `eg.load` (`none|stale|pending|error|skipped|results`) dan validasi `_result` yang sama, dihitung ulang atas byte. `stale`, `pending`, `error` tampil apa adanya, tidak pernah sebagai `pass`.

Hanya `textContent`; tanpa penyimpanan, cookie atau tombol; CSP tidak berubah. Pin `STATIC_SHA256` diperbarui di perubahan yang sama.

## 6. Yang tidak ditangkap (batas jujur)
- Kartu menampilkan yang mesin catat; ia tidak menilai apakah contoh cukup mewakili aturan. Angka di prosa issue tidak diperiksa mesin (hanya blok contoh).
- `pass` dapat dipalsukan kode contoh yang sama yang ditulis model (SPEC_EXAMPLE_GATE 5); yang tidak bisa dipalsukan adalah pohon repo dan tes drafter terpisah di audit.
- Hasil penulis adalah hasil di commit beku penulis; item k > 1 baru punya hasil sesudah job code-nya jalan.
- Kartu bisa basi (berkas berubah sesudah dibaca): sha dan `turn` tampil supaya cocok dengan status terminal.

## 7. Tes dan mutan (ditulis sebelum kode)
Tes (tanpa model, tanpa Docker, spawner palsu yang gagal bila dipanggil, dan `subprocess.run`, `subprocess.Popen`, `os.fork` dipatch melempar): kartu PRD (status dari `prd_turns`, panggilan dari blok, `says` selalu bertanda); item k > 1 `not_run` sampai ada berkas intake, lalu `pass`/`fail` dari berkas; audit `after` yang gagal tampil `fail`; jenis `none|stale|pending|error|results` dari kedua berkas; **giliran terakhir hanya balasan** tetap menampilkan contoh issue yang akan di-start; issue atau folder berubah sesudah giliran → `results: null`; `prd_turns[-1].turn = "../x"` tidak membaca di luar direktori job; PRD yang stale (rebase) dan superseded; turn sebelum PR 3 tanpa `examples`; antrean dengan `jobs_dir` lain; id antrean symlink; `queue.json` > 100 KB; `issue-N.md` antrean berubah → `text_matches false`; antrean tanpa git (tanpa HEAD) tetap diturunkan; FIFO sebagai `job.json`; nilai `actual` berstruktur berisi pola kunci ditahan; id ganda; tier_moves rusak dibuang; cap pindai dan `truncated`; 404 untuk jenis yang salah; Host dan metode salah ditolak di rute baru; tidak ada tulis ke disk; `app.js` tanpa sink HTML (tes yang ada diperluas); pin hash cocok.
Mutan: `conversation[-1]` dipakai menggantikan pencocokan `issue_sha256`; pengecekan digest atau `folder_sha` dibuang; pola `turn` dibuang; `UI_ID` dipakai untuk antrean; `derive` yang memanggil git; pemeriksaan `jobs_dir` dibuang; hanya string yang di-scrub (nilai JSON lewat); status tampil saat `stale`; berkas intake dibaca tanpa kuncinya; `no_examples` atau clash tanpa tanda model; hasil dengan id ganda diterima; `says` tanpa tanda; status diambil dari `says`; symlink diikuti; batas ukuran dibuang; `O_NONBLOCK` dibuang; rute POST baru; Host tidak diperiksa; direktori antrean dari klien; `actions` CLI ditampilkan.
